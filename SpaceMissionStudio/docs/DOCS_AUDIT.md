## 1. Scope and method

- **Audited:** the repository's front page (`README.md`), every Markdown
  file SpaceMissionStudio ships or keeps in its folder, the CLI `--help`
  text, and the in-app help (the bundled copy of the user manual).
- **Not audited:** Basilisk's own documentation (`docs/source/`, the
  upstream `README.md` text, `CONTRIBUTING.md`, `examples/`). It belongs to
  the upstream project and stays as it is.
- **Checks:**
  - every documented CLI command and option against `spacemissionstudio
    --help` (a script compared all of them);
  - every internal link and heading anchor, with a script using GitHub's
    heading rules and with `lychee --offline --include-fragments`;
  - every external link, online;
  - facts (counts, versions, platforms, menu names) against the code;
  - the install and first-run steps of `GETTING_STARTED.md`, run in a new
    virtual environment with an empty reference-data cache (section 4).

Severity: **High** means a newcomer is blocked or misled into a failure.
**Medium** means the text is wrong or out of date but does not block.
**Low** means it is cosmetic or a missing convenience.

## 2. Orientation

**Planning documents.** None of `CLAUDE.md`, `docs/SPEC.md`,
`docs/ARCHITECTURE.md`, `docs/PLAN.md`, `docs/DECISIONS.md` or
`docs/DEVIATIONS.md` exists. Their nearest equivalents are the ECSS
documents in `compliance/docs/`:

| Instead of | There is |
|---|---|
| SPEC | `compliance/docs/SRS.md`, the software requirements |
| ARCHITECTURE | `compliance/docs/SDD.md` and `SDD_components.md`, the design |
| DECISIONS | the decision list in `compliance/PROGRESS.md` |
| DEVIATIONS | `compliance/deviations.md` |
| PLAN | `compliance/docs/SDP.md`, the development plan |

**Fork status.** This repository is a fork of
[AVSLab/basilisk](https://github.com/AVSLab/basilisk). The `upstream` git
remote points there, and GitHub lists `AVSLab/basilisk` as the parent.

- Last upstream commit taken: `c1bf0d7d6` (2026-10-02, `v2.12.0-135`),
  the merge base of `develop` and `upstream/develop`.
- Added on top, in 460 commits (416 by Claude):
  - the whole `SpaceMissionStudio/` folder;
  - `.github/workflows/spacemissionstudio.yml`, the tool's CI;
  - a 13-line block at the top of `README.md` pointing to the tool;
  - one blank line at the end of `.gitignore`.
- Nothing else in Basilisk was changed.

## 4. Clean-install run

Steps of `GETTING_STARTED.md` path C, run on 2026-10-10 in a new Python
3.11 virtual environment, in a fresh checkout of `develop`, with an empty
reference-data cache (`XDG_CACHE_HOME` pointed at an empty folder), on
Linux x86_64.

Every step succeeded (exit status 0). The output matched what the guide
says, with the differences in the table below.

| Step | Took | Result |

| `python3 -m venv .venv` | 5 s | OK |
| `pip install "bsk[all]==2.12.0"` | 412 s | OK |
| `pip install -e ".[gui]"` | 68 s | OK |
